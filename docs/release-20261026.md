# Story / Work / Fun 发布（2026-10-26）

本次发布已验收的三幕 Story、Work 两项目、Fun 六项实验，保留 main 已有的 Hero 动效与颜色。Résumé 未验收，未包含其页面、数据、照片、PDF、下载和导航入口；本地原工作区保持不动。

静态站继续使用 Node 22 / pnpm 10 的 GitHub Actions，从 main 发布至独立 Caddy 站点，校验文件清单后原子切换，保留 previous。Pages 独立构建子路径，只有静态预览，无生产 API 跨域授权。

Ask HY 独立运行于非 root 的 ask-hy systemd 服务，Node 22+，仅监听 127.0.0.1:8787。生产凭据位于服务器 /etc/ask-hy.env，权限 0600，由 systemd 读取，绝不进入 dist 或 Git。Caddy 仅在作品集域名代理 API，覆写真实 IP 并限制请求体。其他站点保持原配置。

默认限额：每 IP 12 次/10 分钟，每天 300 次/200000 Token，并发 4，总超时 25 秒。这些计数驻内存，重启重置，不能代替模型平台账单上限。

## 更新与回滚

前端：分支修改、构建检查、人工验收、合并 main，自动发布。静态回滚见原部署文档，通过 portfolio-release rollback 指向此前已验证的 release；旧版没有 Story/Fun 仍可回滚。

API：目前不由静态 Actions 更新。将已验收的 server/ask-hy 代码放入 /srv/ask-hy/releases/<commit>，保留旧 current 指向，在 loopback 验证后原子切换 /srv/ask-hy/current 并重启 ask-hy。验证公网 health 与真实提问。失败时恢复旧指向并重启。首次安装前没有 API 版本；可停用 ask-hy 并恢复作品集 Caddy 的发布前备份，不影响静态站。

服务器 Caddy 配置的修改均先 validate 后 reload。环境文件不随版本回滚覆盖。实际发布与公网验收以本次交付报告及 Actions 记录为准。
